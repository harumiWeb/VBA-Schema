# Lessons learned

- In a VBA class module, Private fields and procedures cannot be accessed through another instance of the same class. For nested schema processing, expose `Internal*` hooks as unsupported internal-only APIs and verify them with VBE compilation evidence.
- Limit `Scripting.Dictionary` input detection to a TypeName check followed by capability checks. Do not turn an input's missing capability into an environment failure; only a missing component required by the library's own Issue generation is an environment error.
- Do not use `xlflow push --fast` for a fresh managed session or fresh workbook probe. Shared push-state cache can incorrectly report unchanged source, so the session owner must import explicitly with `push --session --no-save`.
- When CI uses a pinned CLI, do not depend on `GITHUB_PATH` resolution order. Export the absolute path of a dedicated binary directory through `GITHUB_ENV` and invoke it directly from each step. `go install` may produce `dev/none` build metadata, so download the verified release asset and validate its pinned commit with `version --json`.
- `xlflow fmt` checks VBA source line endings as LF. Windows checkout conversion to CRLF makes every file appear unformatted, so fix `.bas` and `.cls` to `eol=lf` in `.gitattributes`.
- When a PowerShell safety test intentionally runs a failing child process, do not stop at a success message; explicitly finish with `exit 0` so the child's `$LASTEXITCODE` does not leak.
- Do not conflate the numeric subtype accepted by the public schema with the numeric representation safe for constraint comparison. Separate Number acceptance, `Min`/`Max`, and `WholeNumber`, and add a regression test for a finite Double outside the Decimal range.
- For a tracked binary development workbook, use a `.gitignore` exception together with a `.gitattributes` `binary` rule, and let provisioning create it only when missing. Completion requires source push, VBE compilation, behavioral tests, an explicit save, and a clean xlflow status.
